## Log (one line per step)
- Phases 1-2: Claude Code built the skeleton (config, JSON logs, errors, health/ready, Dockerfile, compose, CI), the job API (JSON + upload), idempotency, signed download links, auth + rate limit, worker with atomic claim, signed callbacks and 48 tests (47 pass locally, 1 MinIO test runs only in Docker/CI).
- Phases 3-4: Claude Code wrote intake.py (download limits, ffprobe real-type checks, 48 kHz mono WAV), tts.py (kokoro + mock adapters), transcribe.py (faster-whisper + mock, silent / music-only checks), scenes.py (scene-splitting algorithm), outputs.py (SRT), a first render.py (colour placeholders + burned captions), runner.py (real worker stages) and the tests; installed the ML packages in my .venv and ran one real Kokoro + Whisper job locally. I reviewed and ran it.
- Phases 5-7: Claude Code wrote understand.py (groq / rules / mock, sense dictionary, statistic / name / brand / sensitive detectors, Groq-to-rules fallback), safety.py, providers/ (pixabay_video, pixabay_image_motion, wikimedia with a CC0 / PD / CC BY-only licence filter, generated motion cards, mock, disabled pexels, mid-job override file), rank.py (open_clip scoring + measurable selection rule, ffprobe-verified downloads), the new render.py (time fitting, salient 9:16 crop / blurred fit, Ken Burns, brightness/colour normalisation, segment cache), qa.py, timeline/manifest builders, an SSRF guard, and 106 new mock tests (213 total: 212 pass, 1 MinIO test runs only in Docker/CI). It ran one real local job (Kokoro, Whisper, Groq, Pixabay, CLIP); that run exposed two bugs (full-range yuvj420p output from JPEG photos; Wikimedia returning 403 without a contact in the User-Agent), which it fixed and covered with tests. I reviewed and ran it.
- CI fix + 3 weak spots: Claude Code fixed the Docker/CI build (torch 2.14.1 + torchvision 0.29.1 installed together from the CPU index and pinned in requirements-ml.txt, pip --retries 5 --timeout 60 plus a 3-try loop for the torch step, pip cache mount, one image build in compose and one Buildx build with GitHub Actions layer cache in CI), added a CLIP logo check (reject/penalise by logo-vs-scene gap, calibrated on 31 hand-labelled real Pixabay previews), a CLIP subject-aware crop (left/centre/right/salient windows scored per frame, blurred fit fallback, choice recorded in timeline.json), Groq temperature 0 + full understanding stored per scene with a fingerprint and reused on re-render, and 14 new mock tests (227 total: 226 pass, 1 MinIO test runs only in Docker/CI). It re-ran the real local job three times; the runs showed that Groq at temperature 0 still varies its wording between jobs, that a too-low crop tie margin cut the subject (raised to 0.03), and that one Apple logo on a laptop still got through as "penalised". The Docker/CI changes were not run locally (no Docker on my PC). I reviewed and ran it.
- Phases 8-9 + logo fix: Claude Code added a logo test on 3 frames of every DOWNLOADED clip (a rejected frame rejects the clip; `logo_check` with thumbnail + frames in timeline.json), the clip swap (POST .../scenes/{scene_index}/swap: next_best, provider + clip_id, or clip_url via the SSRF-safe downloader with Pixabay / Wikimedia licence checks or user_supplied licence fields; a swap cache saved by the full job; only that scene re-rendered per ratio; swap history + swap time vs full render time in timeline/manifest; JOB_NOT_READY and NO_ALTERNATIVE_CLIP codes; a small SQLite migration), forced visual_hint as the first query for Groq too, openapi.yaml (OpenAPI 3.1) with a contract test against the app's routes, tools/batch_run.py, scripts/test.ps1, README.md with settings + error tables (checked by tests) and 38 new mock tests (265 total: 264 pass, 1 MinIO test runs only in Docker/CI). It ran one real local job ("Saving money...", 16:9 + 9:16): full render 108.9 s, swap of scene 2 with next_best 23.5 s (only scene 2 changed). The run also showed that the existing thumbnail logo check rejects most Pixabay video candidates (not yet re-calibrated). Docker was not run locally. I reviewed and ran it.
- CI fix + logo recalibration + swap race: Claude Code found the real cause of the CI KeyError (wait_for_job polled every 0.02 s, so a slow machine used up even the tests' 1000/min limit and got a 429 error body), added one shared tests/helpers.py wait_for_job (growing pause, fails with HTTP status + body), switched the rate limit off in the test fixture (on only in the rate-limit tests), split the limit into RATE_LIMIT_POST_PER_MINUTE=30 / RATE_LIMIT_GET_PER_MINUTE=600 (file downloads count for the job owner) with Retry-After, and made tools/batch_run.py back off and honour Retry-After. It replaced the logo margin rule with a CLIP logo probability: the prompts from the brief measured worse than chance on 82 real Pixabay thumbnails it labelled by hand, so it used matched logo / neutral prompt pairs + a 3x3 crop grid, reject > 0.6. Measured: 89% precision, 53% recall, 99% of clean kept; on 40 held-out thumbnails labelled before scoring, 67% / 33% / 97%. Labels, scores, tools/logo_calibration.py and testpack/calibration/logo_report.md (including the clear logos it still misses). It added manifest footage_mix, made the one-swap-at-a-time rule atomic (active_swap_id lock taken with one conditional UPDATE in the same transaction as the insert, 409 SWAP_IN_PROGRESS) with a barrier test that fails without the lock, added 9 new tests and rewrote the logo and rate-limit tests for the new rules. The real "Saving money..." job went from 0 to 2 stock-video scenes out of 3 non-statistic scenes. Docker was not run locally. I reviewed and ran it.
- B-roll Studio web UI: Claude Code built a plain HTML + CSS + JavaScript Studio in app/studio/ (no build step, no CDN), served by FastAPI at GET / and /studio/<file> (fixed file-name pattern, CSP, no-referrer; STUDIO_ENABLED / STUDIO_DIR settings): create panel with voiceover / script / scene-list tabs and six hard-case presets, a stage stepper with polite polling (growing pause, Retry-After on 429), a player per aspect ratio (9:16 in a phone frame), a scene strip (poster frame, licence, badges, relevance bar, logo check, reason, click-to-seek, one-click next_best swap), recent jobs, and insights (footage mix, SVG timing chart, cost, models). Backend additions: one 16:9 JPEG poster frame per scene (thumbnail in timeline.json; a swap re-makes only the swapped scene's), GET /api/v1/jobs and GET /api/v1/config/public, with openapi.yaml, the contract test, README and 23 new tests, including the optional browser test (295 pass, 2 skipped: the optional Playwright test and the MinIO test). Pipeline choices were not changed. It ran the API + worker locally with my real .env and drove the Studio in Edge (Playwright, installed only in a temp folder): "Saving money" 16:9 + 9:16 finished in 114 s (4 scenes: 1 stock video, 1 photo motion, 2 generated cards), and a swap of scene 1 took 22 s, with no browser console errors. The run caught two CSS bugs (chart text outlined by the icon style, collapsed caption switches), which it fixed. I reviewed and ran it.
- Card-text fix + footage speed: Claude Code found that the "21%" card in the real "Saving money" job was a frame of the old count-up animation (40 x 8/15 = 21.3, caught by the poster frame at 0.3-0.63 s; the video also flashed 3%...37%), not an LLM answer. It removed the count-up and added app/pipeline/cards.py: card text built by code from the scene's own words (40%, 40 percent, forty percent, $1.2 million -> $1.2M, Rs 500, 3x, years; percentage/money before a year; subtitle phrase from the same sentence), a guard that drops (with a warning) any LLM card suggestion holding a number the narration does not say, a last check before drawing, and card_text / card_subtitle / card_source / card_numbers in timeline.json. For speed it profiled the footage stage first (one new HTTPS connection per preview: 0.77 s vs 0.18 s pooled; CLIP model load ~10 s inside the job; 10 logo crops for every passing candidate), then added a pooled HTTP client, parallel queries, a two-pass selection (pass 1: FOOTAGE_WORKERS scenes search + score in parallel; pass 2: one scene at a time in order, so the no-repeat rule is unchanged), CLIP batches + preload at worker start, a lazy logo check that gives the same order as checking all, and per-job + cross-job caches (footage_cache.py; FOOTAGE_CACHE_SECONDS). 37 new mock tests (332 pass, 2 skipped). Measured: replaying the old job's 4 scenes with its stored queries picked the same clips with the same scores, footage 79 s -> 26 s; real job (16:9 + 9:16) footage 129.7 s -> 26.5 s, then 20.2 s on a second run with a warm cache; every card frame shows 40%. The real runs also showed that Groq rewords its queries for each new job (the prompt changed), so some clips differed from the old job; that variation is not from the speed changes. TTS/transcribe times were also lower but were not changed in this step. Docker was not run locally. I reviewed and ran it.
